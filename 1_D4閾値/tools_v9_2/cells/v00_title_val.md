# D4 符号 X スタビライザ閾値 — v9.2 正当化コード（L = 3、(E) は L = 3–9）

**実行環境: Google Colab の GPU ランタイムを推奨します（T4 で可）。** 厳密参照計算は $2^{25}$ 成分（`logical_colors="r"`）または $2^{27}$ 成分（`"rgb"`）の状態ベクトルを JAX で扱います。CPU でも動きますが 1 ショット数秒かかります。

このノートブックは、メインのシミュレーションコード（twisted-frame エンジン）の計算が、同じプロトコルの厳密な量子力学計算と一致することを $L=3$ で確かめます。前半のセルはメイン（`D4_v9_2_main.ipynb`）と**同じソースから生成した同じコード**です。
- (A) 幾何の検査: 27 個の dressed X チェックが、フラックスのない（平坦な）部分空間で全て可換であること。
- (B) ロックステップ厳密性テスト: 同じ雑音の実現に対して、twisted-frame エンジンが出した測定結果の確率（0, 1/2, 1）を、独立に実装した密な状態ベクトル計算が再計算して一致を確認します。circuit-level ではゲート単位（CX・CCZ ごと）に故障を入れた密な計算と、メインの故障伝播表を比較します（`r` と、メインの本計算と同じ `rgb` の両方）。
- (C) **物理エラー率–論理エラー率のプロットの比較**: 密な厳密計算と、メインコードと全く同じ経路の twisted-frame エンジンの論理エラー率を、charge 指標と combined 指標の両方で比較します。**v9 では `r` と `rgb` の両方の論理セクターで行います（R1-6）。** 旧研究のサロゲートの曲線（$\kappa$ を変えたもの）は参考として重ねます（初期状態・終端・指標が違う別モデルです）。
- (D)（任意）: 電荷デコーダの事前分布 $\kappa_{\rm dec}$ の調整。
- **(E)（v9.2）: 研究 2・3 と同じ Pauli proxy 方式（Takada–Bartlett–Williamson）で同じ記憶実験を表した独立なエンジンと、twisted-frame エンジンを $L=3,5,7,9$ で軌道ごとに突き合わせます（全ての測定確率と、全ての復号器の補正に対する最終忠実度の一致）。GPU 不要。**

**v9 の変更**: 回路レベル雑音の定義 `CFG["circuit_noise_preset"]`（メインと同じ。既定 `"uniform"` = 研究 3 と同じ定義。CCZ の後は 3 量子ビット脱分極）に密な計算も対応させた（故障の位置を故障表の名前で特定する）。v7 の本番と同じ定義を検証するには `"legacy_v7"` にしてください。JIT の未来境界の扱い（`jit_future_boundary`）もメインと同じです。

出力（`VCFG["out_dir"]`、既定 `d4_v9_2_validation_results/`）: `d4_v9_2_validation_L3_<model>[_<preset>]_C_<r|rgb>.csv / .png / .pdf`、`..._lockstep.csv`、`..._manifest.json`、（D を実行した場合）`d4_v9_2_decoder_kappa_scan_<model>.csv`。
