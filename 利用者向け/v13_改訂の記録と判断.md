### 2.3 判断：誤差棒を ± 標準誤差から「判定に使う 95% の区間」に変えた

`data_intervals.csv` の `lower_decision`・`upper_decision`（Beta 混合の信頼列、その $p$ の候補サイズ全体で同時に 95%）を描いている。理由は 3 つ：(1) 表の判定（`data_certified`＝区間の上端が要求以下、`data_rejected`＝下端が要求より上）と図が 1 対 1 に対応する。(2) 失敗の少ない点で標準誤差は対数軸上で意味を持たない。(3) 失敗 0 の点の三角（v12 でも 95% の上限）と種類が揃う。区間は ± 標準誤差より広いので、図は v12 より「不確かに」見えるが、これが主張の根拠になっている区間である。

### 2.4 配色

色覚多様性に配慮して検証済みのパレットの 1 番（青）と 2 番（橙）を 2 つの方式に、$d$ には青の 1 色相の濃淡（＋マーカーの形）を使い、診断と目安の線は無彩色にした。文字は全て黒〜灰で、色だけで区別する要素は無い（凡例・$d$ のラベル・線種が必ず併用される）。図の中の言葉は英語（`D4 code switching`／`15-to-1 distillation`）。CSV の列名（`kobayashi_*`, `litinski_*`）は研究 4・5 と論文の図のスクリプトが読むので変えていない。

## 3. 直した表示上の不具合（数値には影響なし）

1. **費用の図で、失敗 0 の点が描かれていなかった。** B・$p=10^{-4}$・$d=9$（48,440 ショット、失敗 0）は推定値が 0 で対数軸に載らず、v12 の図では丸が 3 つしか無かった（何の断りも無く 1 点が抜けていた）。v13 は区間の上端に白抜きの三角を描く。回帰テスト `tests/test_v13_figures.py` が「全ての点が描ける」ことを確かめる。

### 6.2 具体的な未解決事項

1. **統合論文の図 4（`論文草稿/統合論文_v13/figures/fig_epsK.pdf`）と発表資料は v12 の体裁のまま。** `scripts/make_figures.py` は `data_intervals.csv` から独自に描いており、誤差棒の種類・失敗 0 の点の扱いが v13 の図と揃っているかは確認していない（読むファイルのパスだけ `results_v13/` に直した。PDF は作り直していない）。論文に v13 の図を使うなら、`figures_v13.py --pdf` の出力に差し替えるか、`make_figures.py` を同じ規則に合わせる。
2. **体積比の下限が弱い条件がある。** 「棄却されない最小サイズ」は、シミュレーションしていない $d\ge11$ を「棄却されない」と数える。A・$p\ge3\times10^{-4}$ と B・$p=10^{-3}$ では $d\le9$ が全てデータで棄却されているので下限は $d=11$ の体積（例：A・$p=10^{-3}$ で 2.29 倍以上）だが、モデルは $d$ を増やしても誤りが下がらないことを示唆しており、実際の比はずっと大きい（または到達しない）可能性が高い。図の注記「$d\ge11$ costs $\ge$ 2.29×」は正しいが控えめな下限である。強めるには $d=11$ の MC（1 点あたりの費用は $d=9$ の数倍）が要る。

### 8.1 方針と、ロジックを壊さないための確認

* **コメントと説明だけの書き換え**は、ファイル（研究 3 はセル）ごとに「docstring を除いた抽象構文木が書き換えの前後で同一」であることを機械的に確かめた。研究 3 のノートは旧版の v9 ノートからビルドする仕組みなので、書き換えはビルド（`build_notebooks_v13.py` の `publication_cleanup`）の最後に当て、ビルド自身がこの検査をする。登録したパターンが 1 つでも見つからなければビルドが失敗する。
* **コードの変更**は次の表のものだけ。いずれも、変更の前後で同じ計算を回して出力が一致することを確かめた（§8.3）。
* 残したもの：長時間の計算を利用者が選んで実行するためのコメントアウト（`# results = run_experiments()` など）と、Colab で Drive を使うときの任意の手順。どちらも利用者向けの切り替えで、使われなくなったコードではない。
